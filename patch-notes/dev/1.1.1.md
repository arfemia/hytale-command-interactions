The Update 7 build of 1.1.0, on the 0.7 server line. `RunCommandInteraction` and its codec are unchanged: a pack written for 1.1.0 runs as it is, except a `RunCommand` step on a held item's `Ability2` or `Ability3` chain, which Update 7 never reaches (below).

- **The 0.7 server line.** The jar's `manifest.json` reads `ServerVersion` `>=0.7.0-pre.0 <0.8.0` (was `>=0.6.0-pre.13 <0.7.0`), and the jar compiles against the Update 7 server. The example pack's `manifest.json` moves to the same range and to `Version` `1.1.1`. The engine checks a pack's `ServerVersion` the way it checks a plugin's and lists a pack that misses as outdated, so the two must move together: the new `ExamplePackManifestTest` reads the processed jar manifest off the test classpath and the pack's manifest from `examples/InteractionCommandsExamples/`, and fails when their ranges differ. `build.gradle` declares the pack's `manifest.json` as an input of `:test` (`examplePackManifest`), so an edit to that file alone reruns the test.
- **A held item's `Ability2` and `Ability3` never fire on 0.7.0.** While a hotbar item is held, Update 7's interaction context sends those two input types to the player's ability slots (the runes), never to the held item, so the item's own chain on either type, and a `RunCommand` step inside it, is never reached, with no log line. `Primary`, `Secondary`, `Ability1`, `Ability4` and `Pick` keep the held-item path, unless an entity-level `Interactions` claim on the player takes the input first: MMO Skill Tree claims `Ability4` and `Pick` by default (never `Pick` in Creative), and `Ability1` to `Ability3` only in its opt-in stance mode, which also always takes `Ability4`. Nothing in this jar can change that routing. `RunCommandInteraction`'s class javadoc says so, and the README's schema reference and Troubleshooting tell pack authors to put the step on `Primary` or `Secondary`.
- **The example potion drinks on the game's own cooldown.** `Example_Command_Potion.json` drops its `ApplyEffect` of `Potion_Stamina_Cooldown`, which Update 7 removed (an unknown effect id fails the pack at load), and inherits the game's own drink cooldown from its parent.
- **The mod's own icon.** `src/main/resources/icon-256.png` ships in the jar, so the game's mod list shows it; `icon-400.png` at the repo root is a larger copy, outside the jar.
- **Build tooling** (not in the jar): `build.ps1` and `examples/build-example-pack.ps1` install into the chosen patchline's client folder rather than `HYTALE_MODS_DIR` (`-ModsDir` still wins, and `HYTALE_MODS_DIR` applies only when no install is found or in a lone clone); the example pack's zip is rebuilt for 1.1.1.
